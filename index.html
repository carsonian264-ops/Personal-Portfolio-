Case study

    
Personal Portfolio


    

      
The problem
My previous portfolio was built from a generic tutorial template: broken
      script/stylesheet references, hotlinked stock photography standing in for real project screenshots, and
      dead # links. It didn't represent real work or reflect how I actually build software.


      
The solution
A rebuild from the ground up — a project-first layout, an honest tech-stack
      breakdown, a live GitHub activity panel, and a rule-based AI assistant — built with zero UI frameworks and
      zero external image dependencies.


      
Technologies
Semantic HTML5, hand-written CSS (custom properties, bento grid, container-aware
      responsive layout), and vanilla JavaScript (IntersectionObserver for scroll reveals, the Fetch API for live
      GitHub data, a small canvas particle field).


      
Features
Sticky accessible navigation, a typing-animated terminal hero, a live GitHub
      activity panel, an interactive command-driven terminal, and a floating AI assistant with suggested
      questions.


      
Architecture
Static site, no build step or backend. JavaScript is split by concern —
      navigation/reveal logic, the terminal engine, the GitHub panel, and the AI assistant — so each piece can be
      swapped independently (e.g. pointing the assistant at a real API later).


      
Challenges
Keeping the futuristic visual language (glow, glass, grid) from overpowering
      readability and contrast, and building an interactive terminal that's genuinely accessible to keyboard and
      screen-reader users.


      
Lessons
A restrained, token-driven design system scales better than one-off styling per
      section — and honesty about what's "real data" vs. "demo" makes a portfolio more credible, not less.
